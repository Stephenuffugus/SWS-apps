## What changed in this session, in the order it happened

1. **Hub was making a false claim.** It printed "Nothing leaves your device. No
   account." above all 24 cards, including the four that are Firebase-backed
   and need a sign-in. Moved the promise onto the cards; those four now carry a
   **Shared online** chip. Counts are derived from the catalogue so they cannot
   drift.
2. **Grade Sheet** built — new gradebook app. Engine has 79 pinned assertions
   including brute-force checks on every drop combination. Never used by a
   teacher.
3. **Trackfit** stripped to a free app — paid tier and photo-ID removed, fonts
   self-hosted. Verified green. **Could not push** (see below).
4. **Planner: four dead controls.** `toast` was not a function so the merge
   arrows threw silently; every control stacked at one coordinate on a phone; a
   duplicate `class` attribute meant painting a weekday label did nothing;
   lunch was five boxes instead of one band.
5. **Planner: the colour system was being deleted on every build.** All the
   colour CSS sat above the base sentinel, which `design/apply.mjs` replaces
   wholesale. Moved to the app layer.
6. **Planner: the customisation was invisible.** Paint handles were
   `opacity:0` until hover and the key rendered nothing until a colour was in
   use. Replaced with a permanent 44px palette strip — pick a colour, click
   boxes.
7. **Deploys were not visible.** Every service worker answered the *page* from
   cache first, so a fix appeared one visit late; Firebase served HTML with
   `max-age=3600`. All 25 workers now fetch the document network-first;
   HTML revalidates.
8. **Planner: colour a single note.** Each line in a box is its own element
   with its own colour. Several notes in one box, each meaning something
   different. Colour is stored beside the text, so text stays plain.
9. **Guards** — see below.

## Guards (`npm run guards`, `npm run guards:live`)

`design/guards.mjs`. Every check exists because something already shipped past
a green test suite.

| guard | the failure it exists for |
|---|---|
| `css-placement` | app CSS above the END sentinel is deleted by the next `design:apply` |
| `stacked-controls` | 30 merge arrows at ONE coordinate on a phone; all present, all handled, all passing |
| `tiny-controls` | anything under 24px, measured at the **label** — that is what a finger hits |
| `throwing-handler` | clicks everything reachable; born from `toast is not a function` |
| `missing-asset` | a referenced file that 404s |
| `stale-deploy` | `--live` loads the real URL in a real browser, because curl bypasses the CDN **and** the service worker |

On its first run it found a live 404 on `specials-planner/sws-backup.js` and a
TypeError in seating-chart's guest delete. It was proved by deliberately
reintroducing the CSS-placement bug and watching the build fail.

**Run `npm run verify` before claiming anything is done.**

## Open — needs the owner

1. **Trackfit is not pushed.** A Codespace token is scoped to the repo it was
   created from, so pushing to `Stephenuffugus/trackfit` returns 403 — the
   account can push, the container cannot. `.devcontainer/devcontainer.json`
   now declares the repo, so a **container rebuild or a new codespace** fixes
   it. The work is parked either way as a two-commit patch series in
   `design/findings/trackfit-free/`, proved to apply cleanly to a fresh clone.
2. **Play signing fingerprint.** All 24 assetlinks hold a placeholder. It comes
   from Play Console → Setup → App integrity **after the first upload** — it is
   not a prerequisite, it is the last step of the first submission.
3. **Domain decision.** The origin is baked into the signed package. Moving
   after launch breaks every installed app and needs a release per app.
4. **Play account type.** Personal accounts have a closed-testing period before
   production unlocks. I could not verify the current numbers — check Play
   Console. An organisation account under the LLC may avoid it.

## Things I got wrong, recorded so they are not repeated

- Verified with `curl`, which bypasses the CDN and the service worker, then
  reported work as shipped that nobody could see. The `stale-deploy` guard
  exists for this.
- Shipped hover-only controls. Hover does not exist on a touchscreen.
- Never opened the planner at phone width and clicked a button. Every control
  was stacked in one pile there.
- Put app CSS inside a generated block and did not notice the build was
  deleting it.
- Deleted untracked files while cleaning up churn and left a live 404.

The common thread: I checked that code was written, not that a person could see
and use it. The guards check the second thing.
